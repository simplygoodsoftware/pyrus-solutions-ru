# Каталог решений Pyrus

Готовые бизнес-процессы для Pyrus, которые можно установить в свою организацию. Каждое решение содержит формы для создания заявок, маршруты их согласования и настройки интеграций с другими системами.

После установки назначьте участников процесса и выполните настройки из инструкции выбранного решения. Формы и маршруты можно изменять в Pyrus под задачи вашей организации.

Установка выполняется через командную строку с помощью утилиты Pyrus CLI. Понадобится учётная запись Pyrus с правами администратора. Ниже описаны подготовка и подключение к Pyrus, а в инструкции каждого решения приведены команды установки и действия перед началом работы.

| Решение | Назначение |
| --- | --- |
| [КЭДО](solutions/kedo/README.md) | Кадровые документы, расчётные листки и отпуска |
| [Авансовые отчёты](solutions/advance-report/README.md) | Согласование расходов, обмен с 1С:Бухгалтерией и подписание документов |

Решения можно устанавливать независимо. «Карточка физлица» и «Карточка сотрудника» устанавливаются автоматически. Если они уже установлены другим решением, используются существующие формы; учётной записи нужен доступ к ним.

## Подготовка

Склонируйте репозиторий командой `git clone` и перейдите в его каталог: `cd pyrus-solutions-ru`. Все дальнейшие команды выполняются из корня репозитория. Каталоги `solutions` и `shared` должны оставаться на своих местах.

Временно перед публикацией требуется название колонки оргструктуры «Руководитель отдела». Если колонка руководителя называется иначе, переименуйте её. Подробнее — в разделе [«Пока не реализовано»](#пока-не-реализовано).

## Установка CLI

**Windows x64 — PowerShell:**

```powershell
irm https://pyrus.com/Binaries/pyrus-cli/latest/install.ps1 | iex
```

**macOS и Linux — терминал:**

```sh
curl -fsSL https://pyrus.com/Binaries/pyrus-cli/latest/install.sh | bash
```

Для обновления CLI повторите команду установки.

Перезапустите терминал. На macOS/Linux выполните указания установщика по добавлению CLI в `PATH`, если они появились. Проверьте версию:

```powershell
pyrus --version
```

Нужна версия **0.12.0 или новее**.

## Подключение к Pyrus

Получите ключ API своей учётной записи: **Настройки → Авторизация → Получить ключ** ([справка](https://pyrus.com/ru/help/api/authorization)). Затем из корня репозитория выполните:

```powershell
pyrus login
```

Введите email и ключ, проверьте показанную организацию и согласитесь создать `pyrus.yaml`. Посмотреть сохранённые подключения: `pyrus whoami`.

## Установка решения

Выполните команды установки и настройки из инструкции [КЭДО](solutions/kedo/README.md) или [авансовых отчётов](solutions/advance-report/README.md). В macOS/Linux заменяйте `\` в путях на `/`.

- `validate` проверяет файлы локально, без обращения к Pyrus.
- `publish --dry-run` показывает изменения без записи в организацию.
- `publish` автоматически создаёт недостающие формы зависимостей, затем публикует решение.
- `--unlisted keep` сохраняет элементы, отсутствующие в бандле. Без этого параметра публикация решения использует режим удаления таких элементов.

В отчёте `created` — создание, `updated` — обновление, `unchanged` — отсутствие изменений, `skipped` — пропуск. При `--dry-run` это только план. После публикации сохраните идентификаторы форм для настройки 1С.

## Обновление решений

Выполните `git pull --ff-only`, затем повторите команды установки выбранного решения.

Чтобы обновить формы «Карточка физлица» и «Карточка сотрудника», опубликуйте `pyrus.hr-core` отдельно. Обновление затронет эти формы во всех решениях, которые их используют:

```powershell
pyrus validate .\shared\hr-core\bundle.pyrus.yaml
pyrus publish .\shared\hr-core\bundle.pyrus.yaml --unlisted keep --dry-run
pyrus publish .\shared\hr-core\bundle.pyrus.yaml --unlisted keep
```

После этого повторите публикацию решения.

## Работа с несколькими организациями

Чтобы установить решение в другую организацию, сохраните её подключение под отдельным именем, например `test`:

```powershell
pyrus login --env test
```

Введите email и ключ API учётной записи этой организации и подтвердите сохранение подключения. При публикации в эту организацию добавляйте `--env test` к команде, в том числе при пробном запуске с `--dry-run`. Без `--env` используется первоначальное подключение.

## Ошибки публикации

| Ошибка | Что делать |
| --- | --- |
| Не найден файл зависимости | Запускайте команды из корня полного клона репозитория с каталогами `solutions` и `shared` |
| Неизвестен флаг команды | Обновите CLI |
| Ошибка авторизации | Повторите `pyrus login` с действующим ключом API |
| Недостаточно прав | Выдайте учётной записи право на действие и объект, указанные в ошибке |
| В форме зависимости нет поля или неверен его тип | Опубликуйте `pyrus.hr-core` по командам из раздела «Обновление решений» |
| Сущность удалена | Если её нужно восстановить, добавьте `--on-deleted restore` к пробной и обычной публикации |

Для отчёта в JSON добавьте `--json`.

## Ограничения

### Пока не реализовано

- Определение колонки руководителя независимо от её названия и языка организации. Колонка создаётся автоматически, но бандлы пока находят её по названию «Руководитель отдела».

- Учёт установленных версий пакетов и проверка совместимости с другими установленными решениями. Требования к версиям проверяются только по локальным файлам пакетов.
- Автоматическое обновление зависимостей. Существующие формы зависимостей пропускаются целиком; для обновления нужна отдельная публикация пакета `pyrus.hr-core`.
- Полная пробная проверка цепочки на ещё не созданных зависимостях. При первой установке `--dry-run` может сообщить о непроверенных ссылках. Если причина только в отсутствующей зависимости, обычная публикация создаст её перед проверкой решения; остальные ошибки нужно устранить заранее.
- Слияние обновления с изменениями, внесёнными в Pyrus вручную. `--unlisted keep` сохраняет элементы, отсутствующие в бандле; свойства элементов, включённых в бандл, могут быть перезаписаны.

### Особенности работы

- При `--unlisted keep` нельзя заменить существующий BPMN-маршрут формы: если маршрут в бандле отличается от маршрута в Pyrus, публикация отклоняется.
- Формы распознаются по кодам, а не названиям. Одноимённая форма без соответствующего кода может остаться рядом с новой.
- Пакеты публикуются последовательно, без отката. При ошибке публикация останавливается, а выполненные изменения сохраняются. После обрыва связи или тайм-аута отчёт может не содержать всех выполненных изменений.
- Если после ошибки «Карточка физлица» или «Карточка сотрудника» создалась не полностью, повторная установка решения её не исправит: CLI увидит существующую форму и пропустит её. Для исправления опубликуйте `pyrus.hr-core` отдельно по командам из раздела «Обновление решений».
