# Каталог решений Pyrus

Готовые бизнес-процессы для Pyrus, которые можно установить в свою организацию. Каждое решение содержит формы, маршруты согласования и настройки интеграций с другими системами.

После установки назначьте участников процесса и выполните настройки из инструкции выбранного решения.

Установка выполняется через командную строку с помощью утилиты Pyrus CLI. Понадобится учётная запись Pyrus с правами администратора.

| Решение | Назначение |
| --- | --- |
| [КЭДО](solutions/kedo/README.md) | Кадровые документы, расчётные листки и отпуска |
| [Авансовые отчёты](solutions/advance-report/README.md) | Согласование расходов, обмен с 1С:Бухгалтерией и подписание документов |

Решения можно устанавливать независимо.

## Подготовка

Скачайте файлы решений через Git:

```powershell
git clone https://github.com/simplygoodsoftware/pyrus-solutions-ru.git
cd pyrus-solutions-ru
```

Все дальнейшие команды выполняются из этого каталога.

## Установка CLI

**Windows x64 — PowerShell:**

```powershell
irm https://pyrus.com/pyrus-cli/install.ps1 | iex
```

**macOS и Linux — терминал:**

```sh
curl -fsSL https://pyrus.com/pyrus-cli/install.sh | bash
```

Для обновления CLI повторите команду установки.

Перезапустите терминал. На macOS/Linux выполните указания установщика по добавлению CLI в `PATH`, если они появились. Проверьте версию:

```powershell
pyrus --version
```

Нужна версия **0.14.0 или новее**.

## Подключение к Pyrus

Получите ключ API своей учётной записи: **Настройки → Авторизация → Получить ключ** ([справка](https://pyrus.com/ru/help/api/authorization)). Затем из корня репозитория выполните:

```powershell
pyrus login
```

Введите email и ключ, проверьте показанную организацию и согласитесь создать `pyrus.yaml`. Посмотреть сохранённые подключения: `pyrus whoami`.

## Установка решения

Выполните команды установки и настройки из инструкции [КЭДО](solutions/kedo/README.md) или [авансовых отчётов](solutions/advance-report/README.md). В macOS/Linux заменяйте `\` в путях на `/`.

- `validate` проверяет файлы локально, без обращения к Pyrus.
- `publish --dry-run` показывает изменения без записи в организацию.
- `publish` устанавливает выбранное решение и необходимые ему формы.

После установки CLI выведет идентификаторы созданных или найденных форм. Они понадобятся для настройки обмена с 1С.

## Обновление решений

Обновление применяет настройки из новой версии решения. Изменения, внесённые в Pyrus вручную, могут быть перезаписаны, а элементы обновляемых форм и справочников, которых нет в новой версии, — удалены.

Выполните `git pull --ff-only`, затем повторите команды проверки, пробной и обычной публикации выбранного решения.

### Обновление форм сотрудников

Вместе с решениями устанавливаются формы «Карточка физлица» и «Карточка сотрудника». Их файлы входят в пакет `pyrus.hr-core`. При первой установке эти формы создаются автоматически; при последующих установках используются существующие.

Для обновления этих форм выполните отдельные команды ниже. Изменения затронут все решения, которые используют эти формы:

```powershell
pyrus validate .\shared\hr-core\bundle.pyrus.yaml
pyrus publish .\shared\hr-core\bundle.pyrus.yaml --dry-run
pyrus publish .\shared\hr-core\bundle.pyrus.yaml
```

После этого повторите публикацию решения.

## Работа с несколькими организациями

Чтобы установить решение в другую организацию, сохраните её подключение под отдельным именем, например `test`:

```powershell
pyrus login --env test
```

Введите email и ключ API учётной записи этой организации и подтвердите сохранение подключения. При публикации в эту организацию добавляйте `--env test` к команде, в том числе при пробном запуске с `--dry-run`. Без `--env` используется первоначальное подключение.

## Ошибки публикации

| Ошибка | Что делать |
| --- | --- |
| Не найден файл зависимости | Скачайте репозиторий целиком через `git clone` и сохраните расположение каталогов `solutions` и `shared` |
| Неизвестен флаг команды | Обновите CLI |
| Ошибка авторизации | Повторите `pyrus login` с действующим ключом API |
| Недостаточно прав | Выдайте учётной записи право на действие и объект, указанные в ошибке |
| В форме зависимости нет поля или неверен его тип | Выполните команды из раздела [«Обновление форм сотрудников»](#обновление-форм-сотрудников) |
| Сущность удалена | Если её нужно восстановить, добавьте `--on-deleted restore` к пробной и обычной публикации |

## Ограничения

### Пока не реализовано

- Проверка совместимости с версиями решений, уже установленными в организации. CLI проверяет версии только в скачанных файлах.
- Автоматическое обновление форм «Карточка физлица» и «Карточка сотрудника» вместе с решением. Если формы уже существуют, CLI оставляет их без изменений. Для обновления выполните [отдельные команды](#обновление-форм-сотрудников).
- Полная пробная проверка первой установки. Если «Карточка физлица» и «Карточка сотрудника» ещё не созданы, `--dry-run` может сообщить о непроверенных ссылках на них. Обычная установка сначала создаст эти формы. Остальные ошибки нужно устранить до установки.

### Особенности работы

- Формы распознаются по кодам, а не названиям. Одноимённая форма без соответствующего кода может остаться рядом с новой.
- При ошибке установка останавливается, но уже выполненные изменения сохраняются. После обрыва связи или тайм-аута отчёт может не содержать всех выполненных изменений.
- Если после ошибки «Карточка физлица» или «Карточка сотрудника» создалась не полностью, повторная установка решения её не исправит: CLI увидит существующую форму и пропустит её. Для исправления выполните команды из раздела [«Обновление форм сотрудников»](#обновление-форм-сотрудников).
